Objetivo

Este laboratório aprofunda a compreensão do NetFlow versão 9 (Flexible NetFlow) demonstrando como os registros de fluxo são criados, armazenados e exportados para um coletor centralizado. O aluno observa os campos dos registros de fluxo para sessões unidirecionais e bidirecionais de tráfego, correlacionando pares de fluxo de entrada e saída pelo roteador de borda.

  • Parte 1: Observar registros de fluxo NetFlow — Uma direção (tráfego saindo para a Internet).
  • Parte 2: Observar registros NetFlow para uma sessão que entra e sai do coletor.

Configuração Flexible NetFlow no Edge

O roteador Edge já está configurado com Flexible NetFlow (versão 9). A configuração define um flow exporter para enviar dados ao coletor, um flow record especificando os campos capturados, e um flow monitor que combina os dois e é aplicado nas interfaces.

! Flow Exporter — destino: NetFlow Collector (10.0.0.100:9996)
flow exporter myflowEx
 destination 10.0.0.100
 transport udp 9996
!
! Flow Record — campos capturados em cada fluxo
flow record rec1
 match ipv4 source address
 match ipv4 destination address
 match transport source-port
 match transport destination-port
 match ipv4 protocol
 collect timestamp sys-uptime first
 collect timestamp sys-uptime last
 collect transport tcp flags
 collect counter bytes
 collect counter packets
 collect interface input
 collect interface output
!
! Flow Monitor — combina record + exporter
flow monitor mon1
 record rec1
 exporter myflowEx
!
! Aplicação nas interfaces (tráfego de entrada)
interface GigabitEthernet0/0
 ip flow monitor mon1 input
!
interface Serial0/0/1
 ip flow monitor mon1 input
!
ip flow-export version 9
Chave arquitetural: O monitor é aplicado em ambas as interfaces (Gi0/0 e Serial0/0/1) na direção input. Isso garante que tanto o tráfego saindo (PC → Internet, capturado em Gi0/0) quanto o tráfego entrando (Internet → PC, capturado em Serial0/0/1) geram registros de fluxo separados no cache, resultando em dois registros por sessão — um para cada sentido.

Campos chave vs. campos de coleta: Os campos match formam a chave do fluxo — se qualquer um diferir, um novo registro é criado. Os campos collect são contadores e metadados acumulados durante o ciclo de vida do fluxo. Esta distinção é central no Flexible NetFlow v9 e ausente no NetFlow tradicional (v5).

Análise e Conclusões

❓ O que é um registro de fluxo NetFlow?

Um registro de fluxo é uma entrada no cache do roteador que representa uma conversa unidirecional entre dois endpoints, identificada por: endereço IP de origem e destino, protocolo L4, portas de origem e destino. O registro é criado no primeiro pacote do fluxo e atualizado com contagens de bytes/pacotes até que o fluxo expire (timeout de inatividade de 15s ou ativo de 30 min). Ao expirar, é exportado para o coletor.

❓ Por que há dois registros para uma mesma sessão ping?

O monitor está aplicado na direção input em ambas as interfaces (Gi0/0 e Serial0/0/1). O tráfego de saída (PC → Internet) entra por Gi0/0, gerando o Fluxo #1. O tráfego de retorno (Internet → PC) entra por Serial0/0/1, gerando o Fluxo #2. São fluxos distintos porque possuem chaves diferentes (endereços fonte/destino invertidos e interfaces diferentes). Isso é uma característica do modelo unidirecional por interface do NetFlow.

❓ O que acontece quando o destino é o próprio roteador?

Quando um PC pinga diretamente o gateway (10.0.0.1 = Edge), o roteador é o destino final do fluxo, não um nó intermediário de roteamento. O pacote entra por Gi0/0 (capturado pelo monitor) mas não é encaminhado — ele é processado localmente. Por isso a interface de saída registra Null, indicando que não houve encaminhamento a nenhuma interface física. O NetFlow ainda registra o fluxo, pois a captura acontece na entrada.
