! SVI de gerenciamento + Default Gateway (Módulo 11)
SW-Acesso-1(config)# interface vlan 1
SW-Acesso-1(config-if)# ip address 192.168.10.2 255.255.255.0
SW-Acesso-1(config-if)# no shutdown
SW-Acesso-1(config)# ip default-gateway 192.168.10.1
Por que o Default Gateway é essencial no switch (Módulo 11): Switches são dispositivos de Camada 2 e não roteiam tráfego entre sub-redes. Sem o ip default-gateway, o switch não sabe para onde enviar a resposta ICMP de volta a um host em outra sub-rede — fazendo o ping ao SVI falhar mesmo que o roteador esteja configurado corretamente.
  • ✓enable secret Cisco12345! — hash MD5 (mais seguro que enable password)
  • ✓SSHv2 ativo com par RSA 1024 bits e domínio cisco.lab
  • ✓VTYs configuradas com transport input ssh — bloqueia Telnet
  • ✓service password-encryption — cifra senhas fracas no running-config
  • ✓Banner MOTD configurado no R1-Borda
  • ✓copy running-config startup-config — configurações persistidas na NVRAM

❓ Como o Traceroute mapeia os saltos?

O traceroute envia pacotes com TTL incrementado a cada rodada. No salto 1, o pacote parte com TTL=1 — o R1-Borda decrementa para 0, descarta o pacote e retorna uma mensagem ICMP Time Exceeded com seu IP (192.168.10.1), revelando o primeiro hop. No salto 2, TTL=2 permite alcançar diretamente o SRV-Web (192.168.20.10), que responde com ICMP Echo Reply, encerrando o trace.

  • ✓Ping loopback 127.0.0.1: 4/4 — pilha TCP/IP operante
  • ✓Ping gateway 192.168.10.1: 4/4 — L1/L2/L3 local OK
  • ✓Ping SRV-Web 192.168.20.10: 3/4 — roteamento inter-sub-rede confirmado (1 timeout ARP esperado)
  • ✓Traceroute: 2 saltos identificados (R1-Borda + SRV-Web)
Módulo 9

Camada de Transporte — Sockets e Sessões TCP

Ao acessar o SRV-Web pelo Web Browser do PC-Vendas (http://192.168.20.10), o TCP estabelece uma conexão pela porta 80. O comando netstat revela os sockets ativos:

C:\> netstat

Active Connections
  Proto  Local Address          Foreign Address        State
  TCP    192.168.10.10:1025     192.168.20.10:80       ESTABLISHED
❓ O que é um socket?

Um socket é o par único endereço IP + número de porta que identifica uma extremidade de uma conexão de Camada de Transporte. No exemplo acima, o socket local é 192.168.10.10:1025 — porta efêmera (atribuída dinamicamente pelo SO ao processo cliente) — e o socket remoto é 192.168.20.10:80 — porta bem-conhecida reservada para HTTP/TCP. O estado ESTABLISHED confirma que o Handshake Triplo TCP (SYN → SYN-ACK → ACK) foi concluído com sucesso antes da transferência de dados.

ProtoTCPProtocolo orientado a conexão (Camada 4)
Local Address192.168.10.10:1025Socket do PC-Vendas — porta efêmera/dinâmica
Foreign Address192.168.20.10:80Socket do SRV-Web — porta bem-conhecida HTTP

  • ✓Sessão TCP ESTABLISHED observada via netstat
  • ✓Porta efêmera (1025) no cliente x porta bem-conhecida (80) no servidor
Módulos 10 e 11

Acesso Remoto Seguro via SSH

A partir do PC-Vendas, é possível gerenciar remotamente o SW-Acesso-2 (sub-rede B) via SSHv2 — validando o Default Gateway configurado no switch e a rota pelo R1-Borda:

C:\> ssh -l admin 192.168.20.2

Password: AdminSSH#2026

SW-Acesso-2> enable
Password: Cisco12345!
SW-Acesso-2#

SW-Acesso-2# show ssh
Connection  Version  Encryption  State       Username
0            2.0      AES256      Session started    admin

SW-Acesso-2# show ip interface brief
Interface        IP-Address     OK? Method Status  Protocol
Vlan1            192.168.20.2   YES manual up      up

SW-Acesso-2# show mac-address-table
Vlan  Mac Address       Type       Ports
1     xxxx.xxxx.xxxx    DYNAMIC    Fa0/1
Fluxo da sessão SSH: O PC-Vendas (192.168.10.10) envia o pacote SSH para 192.168.20.2 — como é uma sub-rede diferente, o pacote vai ao gateway (192.168.10.1 = R1-Borda), que roteia para a sub-rede B. O SW-Acesso-2 recebe, autentica com RSA 1024 bits e abre a sessão cifrada. Sem o ip default-gateway 192.168.20.1 no switch, a resposta não encontraria o caminho de volta para a sub-rede A.
  • ✓SSHv2 configurado em todos os dispositivos (RSA 1024 bits)
  • ✓Acesso remoto cross-subnet: PC-Vendas → SW-Acesso-2
  • ✓Default Gateway nos switches permite roteamento da resposta SSH
  • ✓Telnet bloqueado — VTYs aceitam somente SSH
