Objetivo

Este laboratório demonstra como três tecnologias de registro centralizado — Syslog, AAA/TACACS+ e NetFlow — podem coexistir em uma mesma infraestrutura de rede, cada uma provendo uma camada distinta de visibilidade sobre eventos, autenticações e tráfego.

  • Configurar R1 para enviar mensagens Syslog ao servidor remoto na severidade de depuração.
  • Validar autenticação centralizada via TACACS+ no R2 e confirmar registros de accounting.
  • Monitorar fluxos NetFlow no servidor coletando estatísticas de tráfego IPv4.

Parte 1

Syslog — Registro Remoto de Eventos

O Syslog é o protocolo padrão para envio centralizado de mensagens de log de equipamentos de rede. O R1 foi configurado para encaminhar mensagens de nível 7 (debugging) ao servidor 192.168.20.20 via UDP porta 514.

Configuração Aplicada no R1

R1# configure terminal
R1(config)# logging host 192.168.20.20
R1(config)# logging trap debugging
R1(config)# logging on
R1(config)# service timestamps log datetime msec
R1(config)# end

R1# debug eigrp packets

Evidência — Entradas Syslog Capturadas

Após ativar o debug EIGRP, o servidor Syslog registrou 23+ mensagens consecutivas provenientes do R1. Abaixo uma amostra representativa das entradas coletadas:

Encerramento do Debug

R1# undebug all
R1(config)# no logging on
❓ Pergunta: Quais são algumas das informações incluídas nas mensagens do Syslog?

As mensagens Syslog incluem: timestamp (data/hora do evento com precisão de milissegundos); endereço IP de origem do dispositivo remetente; facilidade e severidade (ex.: LOCAL7, DEBUG — nível 7); identificador do processo ou subsistema que gerou o evento (ex.: EIGRP); e a mensagem descritiva com detalhes do evento ocorrido. Opcionalmente, o número de sequência e o hostname também podem ser incluídos conforme a configuração do dispositivo.

Parte 2

AAA / TACACS+ — Autenticação e Accounting Centralizados

O TACACS+ (Terminal Access Controller Access Control System Plus) é um protocolo AAA que separa as funções de autenticação, autorização e contabilização em um servidor central. O R2 foi configurado como cliente NAS (Network Access Server), delegando a verificação de credenciais ao servidor 192.168.20.20.

Configuração Aplicada no R2

R2# configure terminal
R2(config)# aaa new-model
R2(config)# tacacs-server host 192.168.20.20
R2(config)# tacacs-server key tacacspa55
R2(config)# aaa authentication login default group tacacs+ local
R2(config)# aaa authorization exec default group tacacs+ local
R2(config)# aaa accounting exec default start-stop group tacacs+
R2(config)# end

NetFlow — Monitoramento de Fluxos de Tráfego

O NetFlow é um protocolo da Cisco que captura metadados sobre cada fluxo IP que atravessa um roteador. Os dados são exportados para um NetFlow Collector que consolida estatísticas de tráfego por origem, destino, protocolo e portas, sem armazenar o conteúdo dos pacotes.

Verificação do Estado Inicial

Antes de gerar tráfego adicional, o NetFlow Collector registrava 182 fluxos e exibia um gráfico de pizza com 3 segmentos de origens IPv4, agrupados por endereço IP de origem.

❓ Pergunta: Quais são alguns dos tipos de informações fornecidas pelo NetFlow?

O NetFlow fornece metadados sobre cada fluxo IP: endereços IP de origem e destino; protocolo da camada 4 (TCP, UDP, ICMP, etc.); portas de origem e destino; interface de entrada no roteador; contagem de pacotes e bytes transferidos; timestamps de início e fim do fluxo; flags TCP acumulados; e campo ToS/DSCP para qualidade de serviço. Essas informações permitem análise de tráfego, detecção de anomalias, planejamento de capacidade e faturamento sem expor o conteúdo dos pacotes.

Resumo das Tecnologias

Tecnologia Protocolo Servidor Dispositivo Finalidade
Syslog UDP 514 192.168.20.20 R1 Registro de eventos do sistema
TACACS+ TCP 49 192.168.20.20 R2 Autenticação e accounting de acesso
NetFlow UDP 2055 192.168.20.20 R1/R2 Monitoramento e análise de fluxos IP
Conclusão: As três tecnologias complementam-se para fornecer uma visão completa da rede. Syslog registra o que aconteceu nos dispositivos; TACACS+ registra quem acessou e quando; NetFlow registra quais tráfegos fluíram pela rede. Juntas, formam a base de um sistema de monitoramento defensivo (SOC).
